# 协作入口

总控维护用户要求、运行 ID、来源索引、页面方案和当前审阅状态。根据任务依赖调用实际子 agent，按宿主并发限制执行；不同职责读取各自 brief。

| 当前工作 | 阅读 | 应收到的结果 |
| --- | --- | --- |
| 论文与项目材料分析 | [领域分析](roles/analysis.md) | 知识、证据、素材与缺口 |
| 汇报结构与逐页内容 | [汇报策划](roles/planner.md) | 整稿大纲与可追溯页面方案 |
| 模板与图文安排 | [版式设计](roles/designer.md) | 统一风格下的页面布局方案 |
| 制作或修改演示文稿 | [PPT 制作](roles/writer.md) | PPTX、预览、渲染报告 |
| 样稿或整稿复查 | [质量检查](roles/quality.md) | 页面问题、依据与复查结果 |

## 给子 agent 的任务

写明职责、目标项目与 run、可读输入路径、允许写入的输出路径、当前阶段和完成条件。附对应 brief 的实际路径；按需补充相关规则，不把全部项目文件和所有参考资料一次性注入。

每次交接使用真实 agent ID，通过运行时 `handoff` 保存输入、输出、状态和摘要。角色提交的每个科学结论关联当前项目来源 ID；页面 ID 沿制作和检查过程保持一致。

领域分析与独立的模板勘察可并行；最终排版依赖内容方案。PPT 制作职责统一写入同一演示文件，其他角色返回内容方案或修改请求。子 agent 未完成或有问题时记录实际状态，总控解决依赖后继续。
